# وثيقة المعمارية التقنية الموصى بها (System Architecture Document) - المُحدّثة
## منصة الغياب والمساءلات الإدارية المدرسية (Administrative Absence Platform)
**الإصدار:** 2.0 (المعمارية المعيارية الحديثة المتوافقة مع معايير الأمان السحابي والنسخ الاحتياطي Sprint 10)

---

## 1. المقدمة والتحسينات المعمارية الحديثة (Architecture Overview & Updates)

تم تحديث المعمارية التقنية للمنصة بناءً على متطلبات الإنتاج المتقدمة (Production Readiness) ومعايير الأمان الصارمة لحماية السجلات الإدارية والمالية للمدرسة، وتضمنت التحديثات المعمارية الرئيسية:
1. **حماية المسارات على الحافة (Edge Route Protection عبر Middleware):**
   - حظر الوصول غير المصادق للمسارات الإدارية الحساسة قبل وصول الطلب إلى خوادم التصيير أو استدعاءات قاعدة البيانات.
2. **تأمين قاعدة البيانات والتخزين السحابي (Production Zero-Trust Security):**
   - إلغاء السياسات العامة المفتوحة للـ `anon`.
   - عزل صلاحيات الزوار لتقتصر على الرموز الأمنية المشفرة (`token-based`) للغياب والتأخر فقط.
   - تحويل حاوية المرفقات الطبية (`absence-attachments`) إلى حاوية خاصة (`public = false`)، وقصر قراءتها على المستخدمين الإداريين الموثقين لحماية خصوصية التقارير المرضية للمعلمات.
   - استبدال الحذف التدميري `ON DELETE CASCADE` بـ `ON DELETE RESTRICT` لحماية سجلات الغياب والقرارات الإدارية من الحذف العرضي عند حذف معلمة.
3. **طبقة إدارة إعدادات المنشأة السحابية (Cloud School Settings Service):**
   - إنشاء خدمة مركزية موحدة (`schoolSettingsService`) لإدارة اسم المدرسة، هوية المديرة، ختم المدرسة، وتوقيعها الإلكتروني مع التحديث اللحظي عبر البث السحابي (Realtime CDC).
4. **سجل التدقيق والمراقبة الإدارية (Audit Trail Service):**
   - تتبع وتوثيق كافة العمليات الإدارية الحساسة (استخراج التقارير، إصدار قرارات الحسم، التعديل على بيانات المعلمات) في جدول `audit_logs`.
5. **نظام استعادة الكوارث والنسخ الاحتياطي (Disaster Recovery Engine):**
   - وحدة متكاملة لإنشاء وتصدير واستيراد لقطات النظام بالكامل (`JSON Snapshot`).

## 2. الهيكل التقني المعتمد والمُحدّث (Standardized Tech Stack)

| المكون التقني | التقنية المعتمدة | الدور والمسؤولية |
| :--- | :--- | :--- |
| **إطار العمل** | Next.js 14+ (App Router) | التوجيه، التخطيطات الإدارية، واجهات العرض، وMiddleware الحماية. |
| **لغة البرمجة** | TypeScript 5.7+ | التحقق الصارم من الأنواع لكافة الكيانات والاستعلامات. |
| **قاعدة البيانات** | Supabase (PostgreSQL 15+) | المصدر الموحد للحقيقة (SSOT)، محرك RLS، ومشغلات المزامنة، والبث المباشر (Realtime CDC). |
| **التخزين السحابي** | Supabase Storage | حاوية `school-assets` (للأختام والتواقيع) وحاوية `absence-attachments` (للمرفقات الطبية). |
| **أمان المسارات** | Next.js Middleware | فحص كوكيز الجلسة (`school_admin_token` و `sb-*`) قبل تمرير الطلب. |
| **التنسيق والتصميم** | Tailwind CSS 3.4+ | تصميم متجاوب يدعم نظام RTL بالكامل مع خط Cairo. |
| **إدارة النماذج والبيانات** | TanStack Query v5 + Context | تكييش فائق، إدارة دورة حياة الاستعلامات، وتحديث فوري للرادار ومؤشرات الأداء. |
| **معالجة وتوليد التقارير** | Custom PDF Print Engines | توليد مستندات رسمية عالية الدقة بنظام Vector A4 متضمنة الختم والتوقيع. |
| **بيئة الاختبارات** | Vitest 2.x | تشغيل 87 اختبار وحدة لضمان دقة العمليات الحسابية والمنطقية. |

## 3. تقسيم الطبقات المعمارية المُحدّث (Multi-Tier Architecture)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Next.js Middleware                              │
│         Edge Token Inspection & Route Guard (/teachers, /procedures)   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Authorized Requests
┌───────────────────────────────────▼────────────────────────────────────┐
│                        Presentation Layer                              │
│   App Router Pages, Domain Modals, Report Center, BackupRecoveryModal  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Calls Reactive Hooks
┌───────────────────────────────────▼────────────────────────────────────┐
│                    Data Fetching & State Layer                         │
│   TanStack Query Hooks, Scoped Contexts, SchoolSettings Broadcaster    │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Executes Pure Domain Logic
┌───────────────────────────────────▼────────────────────────────────────┐
│                       Domain & Service Layer                           │
│   DeductionService, PermissionService, SchoolSettingsService, Audit    │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Strongly-Typed Database Queries
┌───────────────────────────────────▼────────────────────────────────────┐
│                     Repository & API Client Layer                      │
│     Typed Supabase Client, Secure Storage Service, Backup Snapshot     │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Secured by RLS & Foreign Keys

│   8 Operational Tables, Strict RLS, On Delete Restrict, Realtime CDC   │
```

## 4. تفصيل خدمات النظام ومسارات العمل المحدثة (Services Architecture)

### 4.1 خدمة حماية المسارات على الحافة (`middleware.ts`)
تعمل على مستوى Edge Runtime وتقوم بالمهام التالية:
- **المسارات المستثناة (Public Routes):** `/login`, `/inquiry/[token]`, `/teacher-response/[token]`, `/api/health`, والملفات الثابتة (`_next`).
- **المسارات الإدارية المحمية (Protected Routes):** `/teachers/:path*`, `/procedures/:path*`, `/reports/:path*`, `/archive/:path*`.
- **آلية التحقق:** فحص توكن الجلسة من ملفات الكوكيز: `school_admin_token` أو كوكيز Supabase الرسمية (`sb-access-token`, `sb-refresh-token`).
- **إعادة التوجيه الآمنة:** تحويل الزائر غير المصادق فوراً إلى `/login?redirect=[target]` لمنع الوصول غير المصرح به.

### 4.2 خدمة إعدادات المدرسة السحابية والأختام (`schoolSettingsService.ts`)
- **الهدف:** توفير مصدر حقيقة موحد وديناميكي لمعلومات المدرسة والختم والتوقيع، وإلغاء الثوابت النصية الصلبة (Hardcoded Strings).
- **البيانات المدارة:**
  - اسم المدرسة: الثانوية الخامسة مسارات.
  - مديرة المدرسة: فاطمة فلاتة (مع توحيد اللقب إلى "مديرة المدرسة").
  - وكيلة الشؤون التعليمية والمدرسية: أحلام صالح الضبيبي.
  - الختم الرسمي والتوقيع الرقمي: روابط سحابية مخزنة في جدول `school_settings`.
- **المزامنة:** استماع حي لتغييرات الجدول عبر Supabase Realtime مع بث الحدث `school_settings_changed` لتحديث كافة الترويسات والتقارير المفتوحة لحظياً دون الحاجة لإعادة تحميل الصفحة.

### 4.3 خدمة إدارة استئذان الموظفين (`permissionService.ts`)
- **الهدف:** إدارة عمليات خروج الموظفات أثناء الدوام، واحتساب الدقائق التراكمية، ومقارنتها بالحدود الشهرية النظامية.
- **العمليات الأساسية:**
  - `recordPermission`: تسجيل خروج جديد مع احتساب الفارق الزمني عبر `calculateTimeDifference`.
  - `getTeacherMonthlyPermissions`: استخراج إجمالي دقائق واستئذانات معلمة لشهر محدد.
  - `printPermission`: استخراج الاستمارة الرسمية المعتمدة بصيغة PDF.

### 4.4 مركز التقارير ومحرك الطباعة (`reportsEngine.ts` & `reportPdfService.ts`)
- **الهدف:** تجميع ومعالجة السجلات الإدارية المتفرقة وتصديرها بنماذج رسمية متوافقة مع متطلبات وزارة التعليم.
- **التقارير الستة المعتمدة:**
  1. تقرير حصر الغياب الرسمي (شهري / فترات).
  2. تقرير حصر التأخر والانصراف المبكر.
  3. تقرير حصر قرارات الحسم (المادة 21).
  4. سجل المعلمة التفصيلي الشامل (يجمع الغياب + التأخر + الاستئذان + قرارات الحسم في مستند واحد).
  5. تقرير حصر استئذان الموظفين الإجمالي.
  6. سجل استئذان موظفة فردي تفصيلي.
- **التوقيع والختم:** إضافة ختم المدرسة الرسمي المعتمد وتوقيع المديرة فاطمة فلاتة تلقائياً على كافة التقارير المنشأة.

### 4.5 خدمة تدقيق العمليات الإدارية (`auditLogger.ts`)
- توثيق كل عملية إدارية حساسة في جدول `audit_logs`:
  - نوع العملية (`action`): مثل `GENERATE_REPORT`, `CREATE_DEDUCTION`, `IMPORT_TEACHERS`, `UPDATE_SETTINGS`.
  - نوع الكيان ومعرفه (`entity_type`, `entity_id`).
  - تفاصيل إضافية (`details` بصيغة JSONB).
  - هوية المستخدم والتاريخ بتوقيت الرياض.

### 4.6 محرك النسخ الاحتياطي واستعادة الكوارث (`backupService.ts`)
- **تصدير النسخة الاحتياطية (Full Export):**
  - استخراج كامل الجداول الثمانية كلقطة مصفوفة JSON موحدة.
  - تضمين نسخة من الإعدادات وسجلات التدقيق وبيانات المعلمات النشطة والمؤرشفة.
  - حفظ الملف بتسمية دقيقة: `school_backup_YYYY-MM-DD_HH-mm.json`.
- **استعادة النسخة الاحتياطية (Full Restore):**
  - فحص بنية الملف والمفاتيح والتأكد من توافق المخطط (Schema Validation).
  - كتابة البيانات بحركات متسلسلة تضمن عدم تعارض المفاتيح الأجنبية.

## 5. الأمان وحماية البيانات (Sprint 10 Security Architecture)

### 5.1 سياسات الوصول على مستوى الصفوف (Row Level Security - RLS)
- **قاعدة الصفر ثقة (Zero-Trust Model):**
  - الوصول العام (`anon`) محظور تماماً عن كافة الجداول الإدارية.
  - يُسمح للـ `anon` فقط بـ:
    1. استعلام وتحديث سجل المساءلة الخاص به إذا وفّر رمز `token` صالح وغير منتهٍ.
    2. استعلام وتحديث سجل تنبيه التأخر الخاص به إذا وفّر رمز `share_token` صالح وغير منتهٍ.
    3. قراءة بيانات الهوية البصرية من `school_settings` لعرض الترويسة في بوابات المعلمات.
  - الحسابات الموثقة (`authenticated`) تمتلك الوصول الإداري الكامل مع التوثيق في سجل العمليات.

### 5.2 أمان التخزين السحابي (Storage Security)
- **حاوية `absence-attachments`:** خاصة (`public = false`). الرفع متاح للمعلمة عند تعبئة الإفادة، لكن القراءة والتحميل مقتصرة حصرياً على الإدارة الموثقة (`authenticated`) لحماية خصوصية التقارير المرضية الصادرة من منصة صحتي.
- **حاوية `school-assets`:** قراءة عامة للترويسات والتقارير، ولكن الرفع والتعديل والحذف مقصور على الإدارة الموثقة فقط.

### 5.3 سلامة القيود العلائقية (Relational Data Integrity)
- استبدال `ON DELETE CASCADE` بـ `ON DELETE RESTRICT` في جداول:
  - `absence_records`
  - `delay_notices`
  - `deduction_decisions`
  - `employee_permissions`
  - *الهدف:* منع أي مسح تدميري غير مقصود لسجلات الغياب أو الاستئذان أو قرارات الحسم النظامية الصادرة، وفرض مبدأ الأرشفة المنطقية (`Soft-Delete`) كمسار وحيد.
