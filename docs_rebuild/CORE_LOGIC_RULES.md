## 2. محرك احتساب ساعات التأخر وقرارات الحسم (Article 21 Engine)

### 2.1 المرجعية النظامية
يستند المحرك إلى:
- **المادة (21) من لائحة نظام الخدمة المدنية:** حسم ساعات ودقائق التأخر والخروج المبكر غير المعذورة إذا بلغت ما يعادل يوم عمل كامل.
- **القرار الوزاري رقم 1/1139 وتاريخ 17/3/1421هـ:** تفويض مديرة المدرسة بصلاحية إصدار قرارات الحسم.
- **النموذج الرسمي المعتمد رقم (19) (رمز النموذج: و.م.ع.ن - 02 - 03).**

### 2.2 الثوابت والمعادلات الحسابية (Math & Formulas)
```typescript
export const MINUTES_PER_WORK_DAY = 420; // 7 ساعات عمل رسمية = 420 دقيقة
export const MINUTES_PER_HOUR = 60;      // 60 دقيقة في الساعة
export const WARNING_THRESHOLD_MINUTES = 240; // 4 ساعات عمل = 240 دقيقة (عتبة الإنذار المبكر)
```

1. **معادلة أيام الحسم (Deduction Days):**
   $$\text{DeductionDays} = \lfloor \frac{\text{TotalMinutes}}{420} \rfloor$$
   *أمثلة:*
   - أقل من 420 دقيقة (مثل 419 دقيقة) = 0 يوم حسم.
   - 420 دقيقة (7 ساعات) = 1 يوم حسم.
   - 840 دقيقة (14 ساعة) = 2 يوم حسم.
   - 1260 دقيقة (21 ساعة) = 3 أيام حسم.

2. **معادلة الدقائق المتبقية المرحلة (Remainder Carry-Over):**
   $$\text{RemainderMinutes} = \text{TotalMinutes} \pmod{420}$$
   *حالة حافة (Edge Case):*
   إذا كان لدى المعلمة 500 دقيقة تأخر:
   $$\text{DeductionDays} = \lfloor 500 / 420 \rfloor = 1 \text{ يوم حسم}$$
   $$\text{RemainderMinutes} = 500 \pmod{420} = 80 \text{ دقيقة}$$
   يتم إصدار قرار بحسم يوم واحد، وتُرحل الـ 80 دقيقة الفائضة تلقائياً لتُضاف إلى أول تنبيه تأخر لاحق ولا تضيع.

3. **حساب إجمالي الساعات المقربة (Total Formatted Hours):**
   $$\text{TotalHours} = \frac{\text{round}\left( \frac{\text{TotalMinutes}}{60} \times 10 \right)}{10}$$
   *مثال:* 500 دقيقة $\rightarrow 500 / 60 = 8.333... \rightarrow 8.3$ ساعة.

### 2.3 تصنيف حالات المعلمة الإدارية (Status Classification)
- **عادي (Normal):** إجمالي الدقائق غير المعذورة أقل من 240 دقيقة (أقل من 4 ساعات).
- **إنذار مبكر (Warning):** من 240 دقيقة وحتى 419 دقيقة (من 4.0 إلى 6.9 ساعة). يُظهر النظام بطاقة صفراء للمتابعة ولفت النظر.
- **مستحق للحسم الفوري (Due For Deduction):** 420 دقيقة فما فوق ($\ge 7$ ساعات). يُظهر النظام بطاقة حمراء وزر إجراء سريع: "إصدار قرار الحسم الآن ⚡".

### 2.4 قواعد تصفية وتسوية المخالفات (Notice Settlement & Deduplication)
- **شرط استحقاق الدقائق للحسم:**
  يُعتبر تنبيه التأخر مستحقاً للحسم فقط إذا تحققت كافة الشروط التالية:
  1. `isArchived === false` (التنبيه غير مؤرشف).
  2. `status === 'completed'` (اكتملت دورة حياة التنبيه).
  3. `directorOpinion === 'rejected_with_deduction'` (قرار المديرة: عذره غير مقبول ويحسم عليه).
- **منع الازدواجية (Settlement Array):**
  يحتوي كل قرار حسم على مصفوفة `settledNoticeIds`. عند احتساب رصيد المعلمة، يتم استبعاد أي تنبيه مدرج ضمن هذه المصفوفة لمنع حسم نفس الواقعة مرتين.

## 3. حساب الفوارق الزمنية والتنسيق اللغوي العربي (Time Arithmetic & Linguistics)

### 3.1 حساب الفرق بين وقتين (Time Difference Algorithm)
- يقبل النظام الأوقات بصيغة `HH:MM` بنظام 24 ساعة.
- **حالات الحافة الملزمة:**
  - إذا كان الوقت المدخل غير مكتمل أو بصيغة غير صالحة $\rightarrow$ إرجاع `isValid: false`.
  - إذا كان وقت النهاية يساوي أو يسبق وقت البداية (`diffMinutes <= 0`) $\rightarrow$ إرجاع خطأ صريح: "وقت النهاية يجب أن يكون بعد وقت البداية" (لا يسمح بالنقل بعد منتصف الليل في سياق الدوام المدرسي).
  - احتساب الدقائق الإجمالية:
    $$\text{DiffMinutes} = (H_{\text{end}} \times 60 + M_{\text{end}}) - (H_{\text{start}} \times 60 + M_{\text{start}})$$

### 3.2 قواعد التنسيق اللغوي العربي الفصيح للساعات والدقائق
أثبتت الاختبارات أن التنسيق الحرفي المباشر يُنتج أخطاء لغوية في الخطابات الرسمية الموجهة للوزارة. تطبق المنصة القواعد التالية:
- إذا كانت الدقائق فقط (الساعات = 0):
  - `45 دقيقة`
- إذا كانت الساعات خالية من الدقائق:
  - 1 ساعة $\rightarrow$ `"ساعة واحدة"`
  - 2 ساعة $\rightarrow$ `"ساعتان"`
  - من 3 إلى 10 ساعات $\rightarrow$ `"${hours} ساعات"` (جمع قلة)
  - أكثر من 10 ساعات $\rightarrow$ `"${hours} ساعة"` (مفرد منصوب)
- إذا كانت ساعات ودقائق مركبة:
  - 3 ساعات و 30 دقيقة $\rightarrow$ `"3 ساعات و 30 دقيقة"`
  - 1 ساعة و 15 دقيقة $\rightarrow$ `"ساعة واحدة و 15 دقيقة"`
  - 2 ساعة و 20 دقيقة $\rightarrow$ `"ساعتان و 20 دقيقة"`

## 4. معالجة التوقيت الزمني الحرج لمدينة مكة المكرمة (Asia/Riyadh Timezone Bug)

### 4.1 خطأ منتصف الليل الشهير (The UTC Midnight to 3 AM Shift)
- **المشكلة البرمجية:**
  تعتمد دوال JavaScript الافتراضية مثل `new Date().toISOString()` على التوقيت العالمي المنسق (UTC). وبما أن توقيت المملكة العربية السعودية هو `UTC+3`، فإن استدعاء الدالة بين الساعة 12:00 منتصف الليل وحتى الساعة 02:59 فجراً بالتوقيت المحلي يُرجع تاريخ اليوم السابق!
  *مثال:* الساعة 01:30 فجر يوم الخميس 24 سبتمبر بالرياض تظهر في `toISOString()` كـ `2026-09-23T22:30:00Z` (يوم الأربعاء)، مما تسبب سابقاً في تسجيل غيابات وتنبيهات بتواريخ خاطئة.
- **الحل الجذري المعتمد:**
  استخدام صيغة كندية موحدة مربوطة بتوقيت الرياض:
  ```typescript
  export function getSaudiToday(targetDate: Date = new Date()): string {
    try {
      const formatter = new Intl.DateTimeFormat("en-CA", {
        timeZone: "Asia/Riyadh",
        year: "numeric",
        month: "2-digit",
        day: "2-digit",
      });
      return formatter.format(targetDate); // يُرجع دائماً YYYY-MM-DD بدقة
    } catch {
      // خطة احتياطية في حال تعذر Intl: إضافة 3 ساعات يدوياً
      const saudiMs = targetDate.getTime() + 3 * 60 * 60 * 1000;
      const d = new Date(saudiMs);
      return `${d.getUTCFullYear()}-${String(d.getUTCMonth() + 1).padStart(2, "0")}-${String(d.getUTCDate()).padStart(2, "0")}`;
    }
  }
  ```

### 4.2 مهلة الـ 48 ساعة والتحقق من الصلاحية (Token Expiry)
- تُحسب مهلة الروابط العامة للمعلمات بإضافة 48 ساعة دقيقة:
  ```typescript
  export function calculate48HoursExpiry(baseDate: Date = new Date()): string {
    return new Date(baseDate.getTime() + 48 * 60 * 60 * 1000).toISOString();
  }
  ```
- فحص انتهاء الصلاحية:
  ```typescript
  export function isTokenExpired(expiresAt?: string): boolean {
    if (!expiresAt) return false;
    const expiryTime = new Date(expiresAt).getTime();
    if (isNaN(expiryTime)) return false;
    return Date.now() > expiryTime;
  }
  ```

## 5. محرك استيراد وتطهير بيانات المعلمات (Deduplication & Import Engine)

### 5.1 توحيد الأرقام الشرقية والفارسية (Digit Normalization)
يقوم النظام بتحويل الأرقام المشرقية (`٠-٩`) والأرقام الفارسية (`۰-۹`) إلى الأرقام القياسية (`0-9`):
```typescript
export function normalizeArabicDigits(str: string | number | undefined | null): string {
  if (str === null || str === undefined) return "";
  return String(str)
    .replace(/[٠۰]/g, "0").replace(/[١۱]/g, "1").replace(/[٢۲]/g, "2")
    .replace(/[٣۳]/g, "3").replace(/[٤۴]/g, "4").replace(/[٥۵]/g, "5")
    .replace(/[٦۶]/g, "6").replace(/[٧۷]/g, "7").replace(/[٨۸]/g, "8")
    .replace(/[٩۹]/g, "9");
}
```

### 5.2 التحقق من السجل المدني / رقم الهوية الوطنية (National ID Validation)
- إزالة الفواصل والنقاط والصفر اللاحق الناتج عن الإكسل (`.0`).
- استخراج الأرقام فقط: يجب أن يتكون من 10 أرقام ويبدأ بـ `1` (للمواطنين) أو `2` (للمقيمين).
- في حال الاستيراد، يتم قبول الأرقام من 3 إلى 15 خانة لضمان التوافق مع الحسابات المؤقتة ولكن يُعطى الأولوية للـ 10 أرقام.

### 5.3 التوحيد الصارم لرقم الجوال السعودي (Saudi Mobile Standardization)
تُقبل كافة الصيغ العشوائية الشائعة وتُحول تلقائياً إلى الصيغة الدولية الموحدة `9665XXXXXXXX`:
- `0501234567` $\rightarrow$ `966501234567`
- `+966501234567` $\rightarrow$ `966501234567`
- `00966501234567` $\rightarrow$ `966501234567`
- `501234567` $\rightarrow$ `966501234567`
- `٠٥٠١٢٣٤٥٦٧` $\rightarrow$ `966501234567`
- التحقق عبر التعبير النمطي: `/^9665\d{8}$/`.

### 5.4 معالجة وتطبيع الأسماء العربية للدمج (Arabic Name Normalization)
لمقارنة الأسماء دون الوقوع في أخطاء الإملاء الشائعة:
1. إزالة التشكيل والتنوين (`[\u064B-\u065F\u0670]`).
2. توحيد الألفات: `[أإآٱ]` $\rightarrow$ `ا`.
3. توحيد التاء المربوطة: `ة` $\rightarrow$ `ه`.
4. توحيد الياء والألف المقصورة: `ى` $\rightarrow$ `ي`.
5. دمج المسافات الزائدة والمتعددة في مسافة واحدة.

### 5.5 خوارزمية الدمج والتجميع متعدية الحدود (Union-Find Clustering)
يستخدم النظام بنية معطيات Disjoint-Set Union (Union-Find) لتجميع المعلمات المتطابقات استناداً إلى 5 أبعاد:
1. تطابق المعرف الداخلي (ID).
2. تطابق رقم الهوية الوطنية المنقح ($\ge 3$ خانات).
3. تطابق الاسم المنقح + رقم الجوال المنقح.
4. تطابق الاسم الثلاثي ($\ge 3$ كلمات) + التخصص المنقح.
5. تطابق الاسم الرباعي التام ($\ge 4$ كلمات).

**قاعدة الدمج الذهبية:**
- الاحتفاظ بأقدم سجل أصلي (Oldest Retained Record).
- ملء الحقول الفارغة فقط في السجل المحتفظ به من السجلات المكررة (Update Blanks Only).
- إعادة توجيه كافة المفاتيح الأجنبية لسجلات الغياب والتنبيهات والمساءلات إلى المعرف المحتفظ به قبل حذف السجلات المكررة لمنع الأيتام.

## 6. قواعد المرفقات والوسائط والمهام غير المتزامنة (Attachments & Quota Rules)

### 6.1 الخانات الإلزامية حسب نوع الغياب (Dynamic Attachment Slots)
| نوع الغياب | خانات المرفقات المطلوبة | مستوى الإلزامية |
| :--- | :--- | :--- |
| **مرضي** | 1. إشعار طلب الإجازة من نظام فارس.<br>2. التقرير الطبي المعتمد من منصة صحتي. | إلزامي للجهتين |
| **اضطراري** | 1. إشعار طلب الإجازة الاضطرارية من نظام فارس. | إلزامي |
| **مرافق** | 1. إشعار طلب إجازة مرافقة مريض من نظام فارس.<br>2. التقرير الطبي المعتمد للمريض المرافق له. | إلزامي للجهتين |
| **أخرى** | 1. إشعار الطلب المرفوع في نظام فارس.<br>2. مستندات أو خطابات مؤيدة للظرف الاستثنائي. | إلزامي للجهتين |

### 6.2 ضغط الصور على المتصفح وتفادي تجاوز سعة التخزين
- يتم فحص حجم الصورة: إذا كانت صورة طبية تتجاوز 1 ميجابايت، يتم تصغير أبعادها إلى حد أقصى 1920px مع جودة JPEG بنسبة 0.75 باستخدام Browser Canvas.
- الحفاظ على نسبة العرض إلى الارتفاع (Aspect Ratio).
- منع تخزين ملفات DataURL في LocalStorage إذا تجاوزت 750 كيلوبايت لحماية المتصفح من خطأ `QuotaExceededError` (حيث تبلغ سعة المتصفح 5 ميجابايت فقط).

## 7. أمان التشفير والتحقق الإداري (Auth & Cryptography Rules)

1. **تشفير كلمات المرور (Password Hashing):**
   - خوارزمية SHA-256 عبر `window.crypto.subtle.digest` مع Salt ثابت لحماية الحساب الإداري.
2. **توليد الرموز الآمنة للروابط (Cryptographically Secure Tokens):**
   - استخدام `crypto.getRandomValues` لإنتاج 16 بايت مشفرة وتسطيحها إلى نص Hex بطول 32 حرفاً غير قابل للتخمين.
