# System Administration, DevOps & Backup Guide — منصة الإدارة المدرسية

- **المنشأة:** الثانوية الخامسة مسارات
- **المستوى:** DevOps / Database Administrator / IT Support
- **الإصدار:** 1.0.0

---

## 1. بنية النظام وبيئة التشغيل (System Architecture)
- **Frontend & App Engine:** Next.js 14 (App Router) مع واجهات Tailwind CSS و Lucide Icons و Framer Motion.
- **Backend & Database:** Supabase Cloud (PostgreSQL 15+) مع تشغيل RLS (Row Level Security) وسياسات التخزين السحابي.
- **التخزين السحابي للمرفقات:** Supabase Storage Bucket باسم `absence-attachments`.
- **نظام التكوين والنطاق:** `lib/appConfig.ts` يضمن ديناميكية الروابط واستقلاليتها عن أي مزود استضافة.

---

## 2. إدارة المستخدمين والصلاحيات (Identity & Access Control)
- **الحساب الإداري المعتمد:**
  - المستخدم: `wakila`
  - الاسم الكامل: `أحلام صالح الضبيبي`
  - الدور: `وكيلة المدرسة` (vice_principal)
  - المنشأة: `الثانوية الخامسة مسارات`
- **حساب مديرة المدرسة:**
  - الاسم: `منى محمد الغامدي`
  - الدور: `مديرة المدرسة` (principal)
- **إدارة كلمات المرور:** يتم التشفير والتحقق عبر Supabase Auth مع دعم تغيير كلمة المرور المباشر من واجهة النظام.

## 3. خطة وإجراءات النسخ الاحتياطي (Backup & Disaster Recovery)
1. **النسخ التلقائي السحابي (Supabase Point-in-Time Recovery - PITR):**
   - مفعل يومياً عبر لوحة تحكم Supabase لمشروع الإنتاج مع الاحتفاظ بنسخ لـ 7 أيام متتالية.
2. **النسخ الاحتياطي البرمجي (Snapshot Engine - `lib/backupRecovery.ts`):**
   - يمكن إنشاء لقطة بيانات شاملة بصيغة JSON موقعة رقمياً عبر دالة `generateDatabaseBackupSnapshot`.
   - يتضمن ملف النسخة الاحتياطية: المعلمات، سجلات الغياب، إشعارات التأخر، الاستئذانات، قرارات الحسم، والأرشيف وسجل العمليات.
3. **اختبار الاسترجاع (Restore Verification):**
   - التحقق من التوقيع الرقمي للملف (Checksum Validation) قبل كتابة أي سجل.
   - استعادة البيانات آلياً دون فقد أو تكرار عبر دالة `restoreDatabaseBackupSnapshot`.

## 4. مراقبة الأداء والصحة (Monitoring & Health Checks)
- **فحص صحة النظام:** الرابط المباشر `GET /api/health` يعيد:
  ```json
  {
    "status": "healthy",
    "version": "1.0.0",
    "release": "Sprint-5-Production",
    "services": {
      "frontend": "operational",
      "database": "connected",
      "storage": "ready",
      "securityAuth": "enforced"
    }
  }
  ```
- **سجل الأخطاء المركزي (`lib/errorLogger.ts`):**
  - تتبع الأخطاء البرمجية والتشغيلية مع حجب وتطهير أي بيانات حساسة (PII Sanitization).
- **سجل التدقيق والرقابة (`lib/auditLogger.ts`):**
  - تسجيل كافة العمليات الحساسة (إنشاء، تعديل، حذف/أرشفة، تصدير تقارير) متضمناً اسم المستخدم، التوقيت، وعنوان IP.

---

## 5. خطة الدعم الفني لمرحلة ما بعد الإطلاق (Hypercare Plan)
- **المدة:** 14 يوماً من تاريخ بدء التشغيل الفعلي.
- **نطاق الدعم:**
  1. الاستجابة الفورية لأي بلاغ تشغيلي خلال ساعات الدوام المدرسي (7:00 ص - 2:00 م).
  2. منع إضافة أي ميزات أو تعديلات جديدة غير ضرورية.
  3. حصر التعديلات فقط على معالجة الاختناقات أو استفسارات المستخدمين.
  4. أخذ نسخة احتياطية يومية بعد نهاية دوام كل يوم مدرسي.
